# Migration `2025_10_23_083719_create_instansis_table`

## Fungsi

`instansis` adalah master ruang lingkup organisasi tingkat atas. Ia menjadi parent wajib bagi setiap `unit_kerjas`.

Dalam model legacy SITANGKAS, istilah instansi lebih dekat ke **kelompok/ruang lingkup pengelolaan** daripada selalu berarti satu perangkat daerah konkret.

Contoh:

```text
Instansi: SKPD
Unit kerja: Diskominfo, BKAD, Bappeda, dan seterusnya
```

```text
Instansi: DINKES
Unit kerja: Puskesmas, RSUD, laboratorium kesehatan
```

## Kolom

| Kolom | Fungsi |
|---|---|
| `id` | Primary key internal untuk foreign key dan join cepat |
| `kode` | Identifier stabil untuk source code, seeder, konfigurasi, dan integrasi |
| `nama` | Nama/label resmi ruang lingkup organisasi |
| `nama_singkat` | Nama pendek untuk UI atau laporan |
| `deskripsi` | Penjelasan administratif |
| `is_active` | Menentukan apakah instansi dapat digunakan untuk unit/posisi baru |
| `sort_order` | Urutan tampilan tanpa bergantung pada nama atau ID |
| `created_by_user_id` | Pengguna pembuat record |
| `updated_by_user_id` | Pengguna terakhir yang mengubah record |
| `deleted_by_user_id` | Pengguna yang melakukan soft delete |
| `created_at`, `updated_at` | Timestamp Laravel |
| `deleted_at` | Soft delete |

## Constraint

### `kode` unique

Kode harus stabil dan tidak boleh dipakai ulang untuk arti yang berbeda.

Contoh kode:

```text
SKPD
DIKBUD
DINKES
SETDA
KEC_LOWOKWARU
```

### `nama` unique

Mencegah master ganda dengan nama identik. Jika record pernah dihapus, lakukan restore; jangan membuat master baru dengan identitas sama.

## Relasi

Penghapusan fisik instansi dibatasi selama masih memiliki unit kerja. Gunakan penonaktifan atau soft delete.

## Query yang disarankan

```php
Instansi::query()
    ->where('is_active', true)
    ->whereNull('deleted_at')
    ->orderBy('sort_order')
    ->orderBy('nama')
    ->get();
```

## Larangan untuk AI agent

- Jangan hard-code numeric ID instansi.
- Jangan menghapus instansi dengan unit kerja atau histori posisi.
- Jangan memakai `nama` sebagai kunci business rule.
- Jangan mengubah arti suatu `kode`; buat kode baru bila domain benar-benar berbeda.
