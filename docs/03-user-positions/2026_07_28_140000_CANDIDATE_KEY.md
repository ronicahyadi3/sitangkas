# Migration Documentation

## Migration

`2026_07_28_140000_add_unit_kerja_instansi_candidate_key.php`

## Table affected

`unit_kerjas`

## Purpose

Migration ini menambahkan candidate key:

```text
(id, instansi_id)
```

melalui unique index:

```text
uq_unit_kerjas_id_instansi
```

Tujuan utamanya bukan untuk menggantikan primary key `id`, tetapi untuk menyediakan pasangan kolom yang dapat menjadi target composite foreign key dari tabel `user_positions`.

---

## Why this migration exists

Tabel `user_positions` mempertahankan dua kolom berikut:

```text
instansi_id
unit_kerja_id
```

Karena satu `unit_kerja` sudah terkait dengan satu `instansi`, database harus memastikan bahwa pasangan yang disimpan pada `user_positions` konsisten.

Tanpa composite foreign key, data berikut mungkin tersimpan:

```text
instansi_id   = BKAD
unit_kerja_id = Unit kerja milik Diskominfo
```

Validasi aplikasi saja tidak cukup karena data dapat masuk melalui:

- seeder;
- importer;
- command line;
- queue worker;
- integrasi API;
- SQL manual;
- bug aplikasi.

Candidate key ini memungkinkan database menolak pasangan yang tidak valid.

---

## SQL meaning

Secara konseptual migration membuat:

```sql
ALTER TABLE unit_kerjas
ADD CONSTRAINT uq_unit_kerjas_id_instansi
UNIQUE (id, instansi_id);
```

Walaupun `id` sendiri sudah unik sebagai primary key, pasangan `(id, instansi_id)` tetap diperlukan sebagai candidate key yang sesuai dengan susunan kolom target composite foreign key.

---

## Dependency

Migration ini wajib dijalankan sebelum:

```text
2026_07_28_140100_create_user_positions_table.php
```

Migration `user_positions` membuat foreign key:

```text
user_positions(unit_kerja_id, instansi_id)
    → unit_kerjas(id, instansi_id)
```

Tanpa candidate key tersebut, MySQL dapat menolak pembuatan composite foreign key.

---

## Preconditions

Sebelum menjalankan migration:

1. Tabel `unit_kerjas` harus sudah ada.
2. Kolom `unit_kerjas.id` harus tersedia.
3. Kolom `unit_kerjas.instansi_id` harus tersedia.
4. Tipe data dan unsigned state harus kompatibel dengan kolom pada `user_positions`.
5. `unit_kerjas.instansi_id` harus berisi nilai yang valid.

Karena `id` adalah primary key, duplikasi pasangan `(id, instansi_id)` secara normal tidak mungkin terjadi.

- memastikan tipe `user_positions.unit_kerja_id` cocok dengan `unit_kerjas.id`;
- memastikan tipe `user_positions.instansi_id` cocok dengan `unit_kerjas.instansi_id`.

AI agent tidak boleh:

- mengganti urutan menjadi `(instansi_id, id)` tanpa menyesuaikan foreign key;
- mengganti validasi database dengan validasi controller saja;
- membuat `unit_kerja_id` dan `instansi_id` dapat menunjuk ke organisasi yang berbeda.

## Rollback behavior

Method `down()` menghapus unique index:

```text
uq_unit_kerjas_id_instansi
```

Rollback migration ini hanya aman setelah tabel atau foreign key `user_positions` yang bergantung padanya sudah dihapus terlebih dahulu.

Urutan rollback normal Laravel harus:

```text
user_position_documents
user_positions
candidate key unit_kerjas
```

## Validation query

Setelah migration, periksa index:

```sql
SHOW INDEX FROM unit_kerjas
WHERE Key_name = 'uq_unit_kerjas_id_instansi';
```

Periksa konsistensi unit kerja dan instansi pada data lama sebelum membuat foreign key:

```sql
SELECT
    up.id,
    up.unit_kerja_id,
    up.instansi_id AS user_position_instansi_id,
    uk.instansi_id AS unit_kerja_instansi_id
FROM user_positions AS up
JOIN unit_kerjas AS uk
    ON uk.id = up.unit_kerja_id
WHERE up.instansi_id <> uk.instansi_id;
```

Query kedua relevan ketika melakukan migrasi dari skema lama. Hasilnya harus dibersihkan sebelum composite foreign key diterapkan.
